## 2. 핵심 발명 포인트

민기님 아이디어의 본질은 이것입니다.

> CPU 온도만 보는 것이 아니라, CPU → TIM → TC → Heatpipe/Vapor Chamber → T1/T2 → Fan 쪽으로 이어지는 열 흐름의 “온도차, 변화량, 시간지연”을 이용해 히트싱크/써멀 계면/TIM/FAN/사용 자세 문제를 분리 진단하는 구조입니다.

즉 단순히 “CPU가 뜨겁다”가 아니라,

|관측 패턴|추정 원인|
|---|---|
|CPU 온도만 급상승, TC/T1/T2 상승이 작음|CPU–TC 사이 TIM 열화, 접촉압 저하, grease pump-out|
|TC는 오르는데 T1/T2 전달이 늦음|Heatpipe/VC 내부 성능 저하, 접촉 불량, 센서 접촉 불량|
|T1/T2 모두 높고 FAN Max인데 냉각 안 됨|Fan/Fin 먼지, 배기 막힘, duct 문제|
|T1–T2 온도차가 비정상적으로 큼|히트파이프 편측 손상, VC 국부 접촉 문제, 조립 편차|
|자세/Grip/가속도 조건이 비정상|진단값 무효 처리 또는 사용자에게 평평한 위치에서 재진단 안내|

TIM2는 CPU와 heat sink 사이의 얇은 열전달층이고, 표면 미세 불균일 때문에 완전 접촉이 불가능하므로 TIM이 계면 열저항을 낮추는 역할을 합니다. Thermal grease는 초기 성능은 좋지만 온도 사이클에서 pump-out 등으로 성능 열화가 발생할 수 있다는 문헌 근거도 있습니다.

## 4. 특허성 평가

### 특허성이 낮은 안

아래 형태는 특허성이 낮습니다.

> CPU/GPU에 부하를 걸고 FAN Max로 돌린 뒤 CPU 온도가 일정 온도 이상이면 히트싱크 이상으로 판단한다.

이건 이미 공정 검사, thermal validation, burn-in, fan diagnostic과 너무 가깝습니다.

### 특허성이 살아나는 안

다음 조합으로 잡아야 합니다.

1. **히트싱크 자체에는 센서를 붙이지 않음**
2. 대신 **보드 또는 sub-board 위 SMD 온도센서**를 사용
3. 히트파이프/VC/히트싱크 edge와 센서 사이를 **공용화 가능한 열전달 접촉부재**로 연결
4. CPU 온도, TC, T1, T2, FAN RPM, CPU/GPU power, 자세 센서값을 함께 수집
5. 온도 절대값이 아니라 **온도차, 상승 기울기, 시간상수, T1/T2 비대칭, 과거 기준값 대비 변화량**을 계산
6. 결과를 Device Care → PC 진단의 **Heatsink Health** 항목으로 표시

이렇게 가면 단순 진단 알고리즘이 아니라 **센서 배치 제약을 해결하는 하드웨어 구조 + 진단 알고리즘 조합 발명**이 됩니다.

## 5. 추천 회피 설계안

### 핵심 구조: SUS + Copper hybrid contact bridge

SUS만 열전달부로 쓰는 것은 추천하지 않습니다. SUS는 스프링성·내구성은 좋지만 열전도 경로로는 구리보다 불리합니다. 그래서 구조는 이렇게 잡는 게 낫습니다.

[Heatpipe / Vapor Chamber edge]
          │
          │ ① Copper thermal shoe
          ▼
 ┌─────────────────┐
 │  Cu 접촉 패드    │  ← 열 수집부
 └──────┬──────────┘
        │
        │ ② SUS spring bracket
        ▼
 ┌─────────────────┐
 │  압착/공차 보상부 │  ← SUS, spring, clip
 └──────┬──────────┘
        │
        │ ③ 절연 thermal pad / film
        ▼
 ┌─────────────────┐
 │ SMD Temp Sensor │  ← Main board or Sub-board
 └─────────────────┘

즉, **구리는 열을 전달하고, SUS는 접촉압과 공차를 보장**하는 역할로 분리하는 것이 좋습니다.
